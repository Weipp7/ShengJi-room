# ITER-020 混合甩牌、强制跟牌与毙牌

## 目标

按用户最终确认的地方规则，甩牌支持单张、对子、拖拉机的任意混合，且跟牌、毙牌、本墩比较和失败罚分都使用同一套组件结构。

## 规则

1. 只有首家所选牌全部属于同一有效花色、至少两张，且整手不是普通单张、对子或拖拉机时，才进入甩牌判定。
2. 切分时先把每一段连续对取为最长拖拉机，再把剩余同牌面拆为对子，其余为单张。
3. 每个组件独立检查其他三家当前手牌，包括甩牌者的对家。副牌甩牌只检查该副花色，断门玩家的主牌不会让甩牌当场失败。
4. 单张只由更大的同花色单张压住；对子只由更大的同牌面对子压住；拖拉机只由同一玩家手中同长度、更大的拖拉机压住。不合并不同玩家的牌。
5. 只要一个组件可被压住，甩牌就失败。强制出失败组件中张数最多的一组，罚分为 `20 × 该组件张数`；张数并列时选较小的组件强制出。
6. 罚分始终归对方：闲家方失败时从闲家总分中扣除，庄家方失败时给闲家总分加分。
7. 其他玩家先跟足领出花色。手牌足够跟满时，先尽量完整匹配领出的拖拉机，再尽量匹配对子，余下作为单张；手牌不足时必须把该花色全部跟出。
8. 副牌甩牌可以被毙，但响应牌必须全部是主牌、张数相同，并完整匹配每一个拖拉机、对子和单张组件。部分匹配或主副混合都不能毙。
9. 多家都成功毙牌时只比较最强类别：只有单张时比较最大单张；有对子但没有拖拉机时比较最大对子；只要含拖拉机就比较最强拖拉机。
10. 失败公告固定提示“甩牌失败，强制出小”、实际强制出的组件和罚分，不公布其他失败组件。

## 配套交互与节奏

- 首家选择两张或以上时，操作按钮显示“出牌 / 甩牌”；跟牌时仍只显示“出牌”。
- 机器人与出牌提示复用同一套结构匹配函数。机器人断门且需要抢分时，只在能够用全主完整匹配甩牌结构时才会毙牌。
- 发牌每轮间隔 350ms，25 轮共约 8.75 秒。

## 验证重点

- 示例切分：`AAKKQQ` 是普通拖拉机；`AAKKJJ` 是拖拉机加一对；`AAKKQJJ` 是拖拉机加一对加单张。
- 覆盖全单张、对子加单张、拖拉机加其他结构、对家导致甩牌失败、副牌甩牌不被主牌当场判失败，以及禁止跨玩家拼牌。
- 覆盖 20/40/更多张数倍数罚分、优先强制出的失败组件、全主完整匹配及多人毙牌的最强组件比较。
- 全量单元测试、类型检查、生产构建和浏览器端到端检查均需通过。

## 回滚方式

回滚 `packages/game` 中的混合切分和匹配函数、机器人与界面文案以及对应测试。发牌节奏可以独立恢复 `DEAL_TICK_MS`。
